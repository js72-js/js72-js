<product_requirements>
The user requested an Android application for sales management, initially specifying a MySQL database (though MongoDB was adopted). The application should allow product entry, sales management, stock updates, and purchase recording. Key features include detailed sales recaps (number, total, payment type, date, seller), the ability to put sales on hold, retrieve, and modify them. The shopping cart displays product image, name, price, quantity (increment/decrement), and total. Multi-mode payment is required, with debt recording for partial payments. Products are defined by name, category, code, purchase/selling price, and can only be sold if stock is positive. Purchases must be recapped by date, amount, invoice, and supplier. Authentication involves a splash screen, login with email/password, and three roles: Administrator (full access), Manager (purchases, sales), and Server (sales only). An essential requirement is local storage for sales data in offline mode, with automatic synchronization upon connection. Products, persons, and categories should be editable by selecting them from a list. The application has implemented these features from Phase 1 through 7.
</product_requirements>
